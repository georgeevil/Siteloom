Backfill from the NVR

Asks UniFi Protect what it recorded in a range, then runs those recordings through the same pipeline live ingest uses. This is how a gap left by a crashed or stopped siteloom run gets filled — and, because audio never reaches the detector on a live stream, the only way real levels reach Noise.

No recording window has been registered for {% if cameras|length == 1 %}this camera{% else %}these cameras{% endif %} — which is not the same as "there is nothing to fetch". Scanning is the cheap half: it asks the NVR what it recorded in a range and registers each window as pending. Downloading and indexing them is the expensive half, and it resumes from whatever is still pending.

Archives on disk are not offered here

siteloom backfill <path>, which walks a directory of photos and video, has no per-file checkpointing yet (CLD-12): an interrupted run restarts from the top rather than resuming. Everything on this screen — pending, done, the covered range, the button — rests on the guarantee that a stopped run picks up where it left off, and offering the archive path beside it would extend that promise to a path that cannot keep it. Run it from a shell until it is tracked the same way.
